## 3. 知识检索最优技术路线

推荐采用“查询规划 + 多路召回 + 融合重排 + 可解释引用”的 RAG 链路：

1. 查询理解：识别用户是在找文件、找章节、问事实、做比较、查表格，决定召回策略。
2. Query rewrite：短问题走 HyDE，复杂问题走 multi-query / decompose，保留原始 query。
3. 向量召回：严格使用 KB 创建/重建索引时记录的 `embed_model`。
4. 关键词召回：BM25 / PostgreSQL FTS / Tantivy，覆盖人名、编号、政策条款、精确术语。
5. 元数据召回：文件名、标题、章节、页码、sheet、slide、段落序号单独加权。
6. 融合与重排：RRF 融合 vector / BM25 / title / section，再用 rerank 模型取 TopK。
7. 生成与引用：答案只基于命中片段，引用里带文件名、章节、页码、字符偏移，预览时滚动到命中位置并高亮。

准确率目标不应只用主观“答对”衡量，应建立评测集：Recall@10、MRR、nDCG、Answer Faithfulness、Citation Accuracy、端到端 P95 延迟。目标“98%”建议定义为核心业务评测集 Recall@10 >= 98%，答案引用可信率 >= 95%。

## 4. 编辑器助手 7 大链路计划

| 链路 | 输入范围 | 输出 | 文档动作 |
| --- | --- | --- | --- |
| 普通对话 | 无 / 当前上下文 | Markdown 回答 | 不改文档 |
| 选中内容改写 | selection | 文本 diff | replace selection |
| 光标插入 | cursor / paragraph | 新文本 | insert at cursor / before / after |
| 全文处理 | full document | 全文 diff / 操作列表 | replace doc / batch format |
| 批注审阅 | selection / full | issue JSON | add comment / highlight |
| 报告生成 | full / selected | report card | 侧栏报告 / 插入附录 |
| 大纲成文 | outline | structured document | new doc / replace doc |

自定义助手建议保存为：

```json
{
  "name": "正式化改写助手",
  "input_source": "selection|paragraph|full|cursor",
  "system_prompt": "...",
  "allowed_actions": ["replace_selection", "insert_after", "add_comment"],
  "output_schema": {},
  "review_policy": "apply_after_confirm"
}
```

所有改文档动作必须先生成可审查 action plan，用户确认后执行，并保留 undo 记录。

| 模型设置 | 模型按对话/嵌入/图像/语音/重排分组；默认对话只选 LLM |

### 5.3 检索专项

1. 上传 3 类文件：docx/pdf/xlsx，包含文件名关键词、标题、章节、正文专有名词。
2. 逐项问：文件名问题、章节问题、正文事实问题、跨文件比较问题、表格字段问题。
3. 记录：召回路径、TopK 命中文档、rerank 后排名、答案引用、预览跳转位置。
4. 失败自动归因：未入库、embedding 不一致、chunk 元数据缺失、BM25 未覆盖、rerank 模型不可用、阈值过高。
