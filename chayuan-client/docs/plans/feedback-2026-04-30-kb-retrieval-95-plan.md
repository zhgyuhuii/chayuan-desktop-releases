# 知识检索 95%+ 正确率技术路线

## 目标

- 文档知识库问答 Recall@10 >= 95%，首条命中准确率 >= 85%，回答引用覆盖率 >= 95%。
- 常见问题必须可回答：知识库概览、文件名查询、标题/章节查询、正文语义查询、跨文件综合查询。
- KB 创建时确定嵌入模型；查询阶段严禁由前端覆盖嵌入模型，避免向量空间不一致。

## 当前已修复

- 知识库详情页输入框已锁定当前 KB，不再显示“选择知识库”按钮。
- 嵌入模型入口从通用输入框移除；实际使用的嵌入模型由 KB 自身配置决定。
- 知识库详情问答会按“精准 / 全面 / 速度”传递检索策略；默认全面模式开启 hybrid + rerank。
- 后端新增两类强兜底：
  - “本知识库有什么 / 有哪些文件”直接返回文件清单与索引状态。
  - “提示词文件有什么”这类文件名意图先按文件名召回对应 chunk，再与语义检索融合。

## 推荐检索链路

1. 查询理解：识别概览、文件名、标题、章节、正文语义、比较/汇总、多跳问题。
2. 多路召回：文件名精确/模糊、标题/章节 metadata、BM25、向量检索、HyDE、多查询改写。
3. 融合排序：RRF 合并多路候选，按文件、页码、chunk 去重。
4. 重排：优先使用 reranker；不可用时保留 RRF 排序并暴露诊断。
5. 上下文扩展：命中 chunk 前后邻居合并，避免答案缺上下文。
6. 答案生成：只基于召回证据回答，必须给引用；证据不足时说明缺口并提示可重建索引。
7. 可观测性：返回改写 query、召回路径、命中文件、分数、嵌入模型、0 命中原因。

## 95%+ 技术路线

- 索引侧：上传后抽取文件名、标题、章节、页码、表格标题、段落序号；保留 raw chunk + parent chunk，采用“小 chunk 检索、大 parent 回答”。
- 召回侧：默认全面模式使用 BM25 + dense vector + 文件名/标题 metadata 检索；短问句使用 HyDE，复杂问题使用 multi-query / decompose。
- 排序侧：所有召回结果用 RRF 融合，再用 reranker 做 top 30 -> top 8 精排；没有 reranker 时必须标记降级。
- 回答侧：LLM 只能基于 evidence 作答，输出引用；没有 evidence 不编造，返回“未命中原因 + 建议操作”。
- 稳定性：查询阶段永远使用 KB 创建/重建索引时记录的 `embed_model`，前端不得覆盖；更换 embedding 只能重建索引。
- 可运营：每个 KB 建 golden set，持续统计 Recall@5/10、MRR、引用准确率、0 命中率和 P95 延迟；低于阈值禁止发布或提示重建索引。

## 分阶段落地

- P0：锁定 KB 场景、不暴露 embedding 选择、文件清单问题直答、文件名问题优先召回、0 命中诊断。
- P1：补齐 metadata 抽取、BM25 索引、RRF 融合、reranker 降级提示、检索 trace 面板。
- P2：parent-child chunk、表格/图片 OCR 专用解析、per-KB 同义词和别名词典、自动评测集。
- P3：GraphRAG / RAPTOR / ColBERT 或 ColPali 作为高价值行业 KB 的增强路径，不作为首发默认链路。

## 评估方案

- 建立每个 KB 的 golden set：每个文件至少 3 条问题，覆盖文件名、标题、章节、正文、概览。
- 指标：Recall@5/10、MRR、Citation Accuracy、无证据拒答率、P95 延迟、0 命中原因分布。
- 发布门禁：新增或重建 KB 后自动跑 20 条 smoke；核心行业 KB 每晚跑全量评估。
- 目标定义：用户感知“正确率 95%+”以 Recall@10 >= 95% 与引用覆盖率 >= 95% 作为上线硬指标；最终答案正确率需用人工标注集单独验收。

## 后续增强

- 为上传文档补充标题、章节、页码、段落编号、表格标题等结构化 metadata。
- 对长文档使用 parent-child chunk：小 chunk 检索，大 parent 回答。
- 建立 per-KB 词表与同义词表，支持行业术语、简称、别名。
- 搜索详情页支持点击文档后定位到页码/chunk，并高亮 query term。
